# 第 12 章　开卷与长记忆：RAG 与上下文工程

> **本章新增**：参数记忆与非参数记忆、RAG 流程、向量检索、重排、长上下文扩展、"中间遗失"、上下文工程。
> **前置**：词向量与余弦相似度（§3.3）、注意力（§4.5）、上下文学习（§7.5）、KV 缓存（§11.3）。
> **对应论文**：Lewis et al. 2020（RAG）；Liu et al. 2024（Lost in the Middle）；Beltagy et al. 2020（Longformer，可选）。

## 12.1 模型不知道的三件事

一个训练好的 LLM 有三个知识盲区：

1. **它不知道昨天发生了什么。** 训练数据有截止日期（knowledge cutoff）。
2. **它不知道你的私有数据。** 你公司的文档、你的笔记、你的代码库，不在预训练语料里。
3. **它不知道自己错在哪。** 当它编造一个不存在的事实时，它没有任何"查证"的动作。

前两个是**信息缺失**，第三个是**不可溯源**。三者有一个共同的解法：

> **别让它"记住"，让它"查"。**

## 12.2 两种记忆

2020 年，Lewis 等人提出 **RAG**（Retrieval-Augmented Generation，检索增强生成），
把知识分成两部分：

| | 参数记忆（parametric） | 非参数记忆（non-parametric） |
|---|---|---|
| 存在哪 | 模型权重里 | 外部文档库里 |
| 怎么写入 | 训练（慢、贵） | 增删改查（快、便宜） |
| 可溯源 | 不能 | 能，可给出来源 |
| 容量 | 受参数量限制 | 几乎无限 |
| 时效 | 冻结在训练时 | 实时 |

RAG 的流程是：

```
用户问题
   │
   ├─→ 检索器（retriever）：从文档库里找最相关的 K 段
   │        │
   │        └─→ 向量化 → 相似度搜索 → 重排
   │
   └─→ 把「问题 + 检索到的段落」拼成 prompt → 生成器（LLM）→ 答案
```

论文报告，在三个开放域问答任务上，RAG 刷新了 SOTA，并且生成的答案更具体、更多样。

> **跨领域对照**　这是**开卷考试** vs **闭卷考试**。
> 闭卷考的是"你记住了多少"，开卷考的是"你会不会查、会不会用"。
> 人类文明的一大飞跃，就是学会了把记忆外置：从结绳记事、泥板、竹简、纸张，
> 到图书馆、百科全书，再到搜索引擎。
> 1945 年，Vannevar Bush 在《诚如所思》（*As We May Think*）里描绘了 **Memex**——
> 一个可以存储所有个人书籍与记录、并通过关联路径检索的装置。
> 它被认为是超文本与 RAG 的思想祖先。**八十年前的愿景，今天叫"检索增强生成"。**

## 12.3 检索是怎么做的

### 第一步：切块（chunking）

文档太长，不能整篇塞进上下文，要切成小段（比如 500–1000 token）。
切法很讲究：

- 按段落/标题切，保留语义完整；
- 块之间留一点重叠（overlap），避免把一句话切断；
- 块太大，检索精度下降；块太小，上下文不足。

> 这一步没有"正确答案"，只有权衡。它像编辑做**摘录**：
> 摘得太碎，读者看不懂；摘得太长，重点被淹没。

### 第二步：向量化与相似度

把每个块用嵌入模型（第 3 章的表示学习）变成一个向量，存进**向量数据库**。
查询时，把问题也变成向量，找**余弦相似度**最高的 K 个块。

$$
\cos(\mathbf{q}, \mathbf{d}) = \frac{\mathbf{q}\cdot\mathbf{d}}{\|\mathbf{q}\|\,\|\mathbf{d}\|}
$$

注意：这里用的是第 3 章的词/句向量，但不再是静态的 word2vec，
而是 BERT 家族的**句向量模型**（§6.7 说过，编码器仍是嵌入模型的主力）。

大规模检索不会暴力比对所有向量，而是用**近似最近邻**（ANN）算法，
比如 HNSW（分层可导航小世界图）。这是用一点召回率的损失，换几个数量级的速度。

### 第三步：混合检索与重排

纯向量检索有个弱点：它擅长"语义相似"，不擅长"精确匹配"。
用户搜"Error code 0x80070005"，向量模型可能找出一堆"权限错误"的文档，
但漏掉那个真正写着这个错误码的页面。

所以实践中常用**混合检索**：

- **BM25**（关键词/词频）：精确匹配，擅长专有名词、代码、数字；
- **向量检索**：语义匹配，擅长同义改写、跨语言；
- 两路结果合并，再用一个**重排器**（reranker，通常是交叉编码器）精排。

> **跨领域对照**　这是图书馆的**分类目录 + 主题词表**双轨制：
> 查作者名靠目录（精确），查"关于某个主题的书"靠主题词（语义）。
> 单一检索方式永远有盲区，好的检索系统都是**多路召回 + 融合排序**。

### 第四步：拼进上下文

把检索到的段落和问题一起放进 prompt，让模型"基于给定材料回答"。
工程上通常要求模型：

- 只使用给定材料，不要用内部知识；
- 给出引用编号；
- 材料不足时明确说"不知道"。

> **注意**：这三条都是**提示层面的约束**，不是硬保证。模型仍可能不遵守。
> 真正的保证要靠评测（第 13 章）和结构化输出。

## 12.4 长上下文：把"检索"交给注意力

RAG 是"外部检索"。另一条路是**把窗口开大**，让模型自己从长文本里找。

上下文窗口从 GPT-3 的 2048 token，一路涨到 128K（Llama 3.1）、200K（Claude）、
甚至百万级（Gemini 1.5）。技术上靠的是：

- **RoPE 位置插值/外推**（§5.5）：把训练时没见过的长位置"压缩"到见过的范围；
- **注意力效率**：FlashAttention、GQA、稀疏注意力（第 11 章）；
- **长文本训练数据**：光改位置编码不够，模型得见过长文档。

### "中间遗失"：长不等于会用

2023 年，Liu 等人的实验揭示了一个反直觉的现象：
把关键信息放在长文档的**开头**或**结尾**，模型能找到；
放在**中间**，准确率显著下降，呈 **U 形曲线**。

```
准确率
 高 │ ●                    ●
    │  ●                  ●
    │   ●                ●
 低 │    ●●●●●●●●●●●●●●●
    └──────────────────────→ 关键信息在文档中的位置
      开头      中间       结尾
```

模型不是"均匀地"使用上下文，而是**偏向两端**。

> **跨领域对照**　这是心理学里的**序列位置效应**（serial position effect）：
> 自由回忆一串词时，开头（**首因效应**，primacy）和结尾（**近因效应**，recency）
> 记得最牢，中间最差。Ebbinghaus 1885 年的遗忘曲线、Murdock 1962 年的实验，
> 都记录了这条 U 形曲线。
> **为什么？** 一种解释是：开头的信息进入了长时记忆（复述次数多），
> 结尾的信息还在短时记忆里（刚发生）。中间的被两头挤压。
> LLM 的机制不同（注意力权重、训练数据的长文档分布），但**现象同构**。
> 这提醒我们：**"上下文窗口 100 万 token"不等于"能用好 100 万 token"。**

## 12.5 RAG 还是长上下文？

两者不是替代关系，是不同成本结构的选择：

| | RAG | 长上下文 |
|---|---|---|
| 适合 | 知识库大、更新频繁、要溯源 | 一次性分析整本书/整个代码库 |
| 成本 | 检索便宜，上下文短 | 上下文长，KV 缓存贵（§11.3） |
| 精度 | 依赖检索质量，可能漏 | 全量可见，但中间会丢 |
| 延迟 | 多一次检索 | 首 token 延迟高 |
| 更新 | 改文档即可 | 要重新喂 |

实践中常见的组合是：**先用 RAG 粗筛，再把筛出的内容放进长上下文精读。**
这和人类做研究一样：先查索引找几篇论文，再逐篇精读。

> **"上下文工程"（context engineering）** 这个词在 2025 年流行起来，
> 指的是：**如何为当前任务，构造最合适的上下文**——包括检索什么、放多少、
> 怎么排序、怎么压缩、用什么格式。
> 它把"提示词工程"（prompt engineering）从"措辞技巧"提升到了"信息架构"。
> 某种意义上，这是**人机之间的信息设计学**。

## 12.6 工程陷阱

RAG 看起来简单，落地时坑很多：

1. **检索错，生成一定错。** 检索器没找到正确段落，再强的模型也救不回来。
   这叫 **GIGO**（garbage in, garbage out）。
2. **多跳问题**。"A 的创始人的妻子的公司是哪家？"需要查两次。
   单轮检索搞不定，需要**迭代检索**（iterative retrieval）或 Agent（第 15 章）。
3. **块边界切断语义**。答案横跨两个块，每个块都不完整。
4. **冲突信息**。检索到两份互相矛盾的文档，模型可能各信一半。
5. **引用幻觉**。模型编造一个看起来很像的引用编号。

> **跨领域对照**　这些坑和**法律检索**、**医学循证**的坑一模一样：
> 判例找错，结论就错；指南版本冲突，要说明依据；引用必须可核查。
> 专业领域的检索系统早就有成熟规范（如 PRISMA 的系统综述流程），
> RAG 工程可以直接借鉴：**记录检索策略、保留证据链、标注不确定性。**

---

## 12.7 本章小结

- LLM 有知识截止、私有数据、不可溯源三个盲区；RAG 用**外部检索**补上。
- RAG 流程：切块 → 向量化 → 检索（混合 BM25 + 向量）→ 重排 → 拼进 prompt。
- **长上下文**是另一条路，但"能装下"不等于"能用好"：**中间遗失**呈 U 形。
- U 形曲线与心理学的**首因/近因效应**同构。
- RAG 与长上下文是成本结构不同的两种方案，常组合使用。
- 上下文工程 = 为任务设计信息架构，而不只是措辞。
