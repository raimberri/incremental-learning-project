## 3.1 最笨的办法，以及它为什么不行

要让计算机处理"猫"，先得把"猫"变成数字。最直接的做法是编号：

```
猫 = [1, 0, 0, 0]
狗 = [0, 1, 0, 0]
鱼 = [0, 0, 1, 0]
车 = [0, 0, 0, 1]
```

这叫 **one-hot 编码**。它有两个立刻可见的毛病：

1. **维度爆炸**：词表 5 万，每个词就是一个 5 万维的向量，其中 49999 个是 0。
2. **没有相似性**：任意两个不同的词，内积都是 0，距离都相等。
   在模型眼里，"猫"和"狗"的差距，与"猫"和"车"的差距**一模一样**。

第 1 章说过，n-gram 就死在这一点上。要救，就得让向量携带"意义"。

## 3.2 一个 1957 年的语言学信条

怎么定义"意义"？语言学家 J. R. Firth 在 1957 年写下一句话，后来成了整个领域的座右铭：

> **"You shall know a word by the company it keeps."**
> （观其伴，知其义。）

意思是：一个词的意义，由它经常一起出现的词决定。
"猫"常和"喵""鱼""毛""宠物"一起出现；"车"常和"油""轮胎""驾驶"一起出现。
即使你没见过"猫"的定义，只要看到它的"朋友圈"，也能猜个八九不离十。

这个思想更早可以追到 Harris（1954）的**分布式假设**（distributional hypothesis）：
**上下文相似的词，意义也相似。**

> **跨领域对照**　这也是社会学里"看你跟谁在一起，就知道你是什么人"的量化版，
> 以及网络科学中的**同质性**（homophily）：相似的人倾向于连接在一起。
> 反过来说，从连接模式可以推断属性——社交网络分析、推荐系统、反欺诈，用的都是同一个逻辑。

## 3.3 word2vec：把"观其伴"变成一个训练任务

2013 年，Mikolov 等人在 Google 提出了 **word2vec**。它的想法极其狡猾：

> 既然"意义 = 上下文"，那我就**训练一个模型去预测上下文**。
> 模型训练好了，中间那层用来表示词的向量，就是词义。

具体有两种玩法：

- **CBOW**（Continuous Bag of Words）：用周围的词预测中间词。
  比如用"我、养、了、一、只、很、可爱"预测"猫"。
- **Skip-gram**：反过来，用中间词预测周围的词。
  比如用"猫"去预测"养""可爱""喵"。

以 Skip-gram 为例，目标函数是：

$$
\max \sum_{t}\sum_{-c \le j \le c,\, j\ne 0} \log P(w_{t+j} \mid w_t)
$$

读作：对语料里每个位置 $t$，用中心词 $w_t$ 去预测窗口内（半径 $c$）的每个邻居，
让这些预测的对数概率之和最大。$P$ 用 softmax 算（§1.6 已讲，不再重复）。

训练完成后，每个词得到一个 100–300 维的稠密向量。神奇的事发生了：

```
vec(国王) - vec(男人) + vec(女人) ≈ vec(女王)
vec(巴黎) - vec(法国) + vec(意大利) ≈ vec(罗马)
```

**语义关系变成了向量空间里的位移。** "性别"是一个方向，"国别"是另一个方向，
它们可以像箭头一样被加减。

> 这个结果首次系统展示于 Mikolov 等人 2013 年的另一篇论文
> *Linguistic Regularities in Continuous Space Word Representations*。
> 注意：它是**近似**成立的，不是精确定律；后来的研究发现它依赖于特定的训练细节。

### 负采样：让 softmax 变得可行

上面的 softmax 要对整个词表（几万到几十万）求和，每个样本都算一遍，太慢。
**负采样**（negative sampling）把"多分类"改成"二分类"：

- 正样本：真实出现在上下文里的词对，标签 1；
- 负样本：随机抽几个词，标签 0；
- 训练目标：让正样本得分高，负样本得分低。

这相当于把"从 5 万个词里选出正确的那一个"降级为"判断这一对词是不是真的搭"。
计算量从 $O(V)$ 降到 $O(k)$，$k$ 通常只要 5–20。

> **跨领域对照**　这是**计算复杂度换统计效率**的经典操作，和数据库里的"近似查询"、
> 数值计算里的"蒙特卡洛估计"同一思路：不追求精确答案，追求"足够好的答案 + 快十倍"。

## 3.4 为什么这样能学到语义

把训练过程想成一个约束系统：

- "猫"和"狗"的上下文高度重叠（都会跟"养""可爱""宠物"一起出现），
  所以模型给它们分配相似向量，才能用同一个向量完成相似的预测任务；
- 如果两个词向量差很远，模型就没法用同一套参数预测它们相似的上下文，损失会变大。

于是**梯度下降自动把"上下文相似"压成了"向量相近"**（§2.1 的机制在这里发挥作用）。
没有人告诉模型"猫和狗都是动物"，这个结构是从共现统计里自己长出来的。

> 这就是**表示学习**（representation learning）的核心主张：
> 不要手工设计特征，让模型为了完成某个任务，自己学出有用的内部表示。
> 手工特征像是给人一本词典；表示学习像是把人丢进语言环境里。

## 3.5 词怎么切：从整词到子词（BPE）

还有个前置问题没解决：**词表里的"词"是谁定的？**

按空格切？中文没有空格；英文里 "unbelievable" 和 "unbelievably" 会被当成两个词；
代码、网址、罕见人名、emoji 更是无处安放。词表一大，稀疏问题回来；词表一小，
未登录词（OOV）满天飞。

现代方案是**子词**（subword）：把词切成更小的片段。

```
unbelievable → un + believ + able
tokenization → token + ization
```

最常用的算法是 **BPE**（Byte Pair Encoding，字节对编码）。它的过程简单得像压缩：

1. 初始时，把文本拆成单个字符（或字节）；
2. 统计哪一对相邻符号出现最多；
3. 把这一对合并成一个新符号；
4. 重复 2–3，直到词表达到目标大小（比如 5 万或 12.8 万）。

高频片段（"the""ing"）会早早被合并成一个 token；罕见词则被拆成几个常见片段。
这样**任何字符串都能被表示**，词表大小可控。

> **跨领域对照**　BPE 原本是 1994 年 Philip Gage 提出的一种**数据压缩**算法。
> 二十二年后，Sennrich 等人把它搬来做神经机器翻译的分词。
> 分词和压缩的目标惊人地一致：**用尽量短的编码，表示尽量多的文本。**
> 这也是信息论（§1.4）的老问题——香农当年就在做"如何用最少的比特编码英文"。
> GPT-2 用的是**字节级 BPE**：以字节为最小单位，任何 Unicode 文本都能编码，永不 OOV。

> **定义 3.1（token 与词表）**　token 是分词器输出的最小单位；词表（vocabulary）
> 是所有可能 token 的集合，大小 $V$ 通常 3 万–15 万。
> 一个中文字符可能占 1–3 个 token，一个英文常见词通常 1 个 token。
> 这解释了为什么 API 按 token 计费，以及为什么中文有时"更贵"。

## 3.6 从静态到动态：同一个词，不同的向量

word2vec 有一个根本局限：**每个词只有一个向量**。
但"苹果"在"吃苹果"和"苹果发布会"里意思不同；"bank"在"河岸"和"银行"里也不同。
静态词向量只能取一个折中。

解决办法是**上下文相关表示**（contextual representation）：
不再给每个词一个固定向量，而是让整个句子过一遍网络，
每个位置的向量由"这个词 + 它的上下文"共同决定。

- 2018 年的 ELMo 用双向 LSTM 做这件事；
- 同年 BERT 用 Transformer 做，效果更好（第 6 章会讲 BERT 的训练目标）。

> **这是一个思维方式的转变**：词向量不再是"词典里的条目"，而是"句子在这个位置上的激活"。
> 换句话说，**表示是算出来的，不是查出来的**。
> 在 GPT 里，同一个"苹果"在不同句子中的内部向量确实不同——这是它理解语境的基础。

## 3.7 嵌入层在 LLM 里长什么样

在工程上，嵌入（embedding）就是一个矩阵 $E \in \mathbb{R}^{V \times d}$：
第 $i$ 行是第 $i$ 个 token 的向量。查表就是取一行。

- $V$ 是词表大小（如 128256），$d$ 是隐藏维度（如 4096）。
- 这个矩阵**是可训练参数**，跟着整个网络一起用梯度下降更新（§2.1）。
- 很多模型让输入嵌入和输出层**共享权重**（weight tying），省参数、也常更稳。

一个 GPT-3 级别的模型，$d = 12288$，嵌入矩阵本身就有 $50257 \times 12288 \approx 6.2$ 亿参数。
**光是"查字典"这一层，就比 2012 年的整个 AlexNet 大。**

## 3.8 表示里缺的那一维：顺序

"猫追狗"和"狗追猫"，用的词完全一样，意思相反。
但如果模型只是把每个词的向量取出来、求个平均，这两句话的表示**完全相同**。
这叫**词袋**（bag of words）视角——它丢掉了顺序。

解决办法是给每个位置加一个**位置编码**（positional encoding）：
把"这是第几个词"也变成一个向量，加到词向量上。

$$
\text{输入}_i = \text{词向量}(w_i) + \text{位置向量}(i)
$$

最早的做法是用不同频率的正弦、余弦函数生成位置向量（Vaswani 等，2017）：

$$
PE_{(i,2k)} = \sin\!\left(\frac{i}{10000^{2k/d}}\right),\qquad
PE_{(i,2k+1)} = \cos\!\left(\frac{i}{10000^{2k/d}}\right)
$$

为什么用三角函数？因为它让"相对位置"变得容易计算：
位置 $i+k$ 的编码，可以由位置 $i$ 的编码经过一个**线性变换**得到。
换句话说，模型可以学会"往右看三个词"这种操作。

后来出现了可学习的位置嵌入、**RoPE**（旋转位置编码，Su et al. 2021）等方案，
细节留到 §5.6，因为只有理解了注意力的形式，才能理解 RoPE 在旋转什么。

> **跨领域对照**　位置编码像乐谱里的**小节线**：音符（词）相同，落在不同小节，
> 节奏和意义就不同。也像地图上的**经纬度**：地点本身是内容，
> 经纬度是位置，两者相加才能定位。注意这里"相加"是个数学技巧，
> 并不是真的把"内容"和"位置"混为一谈——这也是类比失效的地方。

## 3.9 表示学习的遗产与陷阱

**遗产**：今天 LLM 的第一层和最后一层，本质上仍是"词向量 + 预测下一个词"。
Bengio 2003 的骨架（§1.3）没有变，变的是中间的架构和规模。

**陷阱**：

- **相似 ≠ 同义**。"医生"和"护士"向量接近，但社会角色不同。
- **偏见会被编码**。如果语料里"医生"更多与"他"共现，"护士"更多与"她"共现，
  向量就会继承这个统计偏见，并在下游任务中放大。
- **各向异性**。实际训练出的词向量往往挤在一个狭窄的锥形区域里，
  直接用余弦相似度衡量意义并不可靠。
- **静态 vs 动态的混淆**。说"词向量"时，要问清楚：是 word2vec 那种查表向量，
  还是 Transformer 某一层的上下文激活？两者不是一回事。

---

## 3.10 本章小结

- one-hot 无法表达相似性；**分布式假设**说"上下文相似的词意义相似"。
- **word2vec** 用"预测上下文"作为训练任务，把语义压进稠密向量；
  **负采样**把昂贵的 softmax 降级为便宜的二分类。
- **BPE** 用数据压缩的思路做分词，兼顾词表大小与覆盖率，永不怕 OOV。
- 表示从**静态**（一词一向量）走向**动态**（上下文决定向量）。
- **位置编码**补上了词袋丢失的顺序信息。
- 表示学习会继承数据里的偏见——这是"从数据里学"的代价。
