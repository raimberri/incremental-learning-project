## 16.2 十条定律

这些不是物理定律，而是**贯穿全课程、反复出现的模式**。每条都标了它第一次出现的地方。

### 定律 1：目标越简单，越容易规模化（§1、§6）

"预测下一个词"简单到可以无限复制到任何文本上。复杂的多任务目标需要复杂的标注与调度。
**简单目标 + 海量数据 > 精巧目标 + 少量数据。** 这是 Sutton "苦涩的教训"的核心。

### 定律 2：表示决定上限（§3）

模型能学到什么，受限于它如何表示。one-hot 学不到相似性，静态词向量学不到语境，
RNN 的固定状态学不到长程依赖。**每一次架构革命，本质都是一次表示革命。**

### 定律 3：注意力是可微检索，深度是串行计算（§4、§5、§9）

注意力让模型"按需回看"，于是信息路径变短；深度让模型"逐步变换"，于是计算有层次；
自回归让"时间"变成"计算"，于是写步骤 = 想更久。
**这三件事拼起来，就是"会思考"的工程近似。**

### 定律 4：规模有定律，定律有边界（§7）

损失随规模按幂律下降，可预测、可规划。但数据会枯竭、推理成本会上升、收益会递减。
**"更大"是一个阶段性的答案，不是终极答案。**

### 定律 5：对齐是分布偏移，不是知识注入（§8）

RLHF 不教模型新事实，它只是把概率质量从"人类不喜欢"挪到"人类喜欢"。
所以对齐能改变风格与行为，但改不了知识边界。**别指望用 RLHF 教会模型它没学过的东西。**

### 定律 6：推理可以写进权重，也可以花在推理时（§9、§10）

训练时的 RL（R1）、推理时的搜索（自洽性、ToT）、提示（CoT），是同一件事的三种时间尺度。
**给定预算，要在"训练更久"与"想更久"之间做最优分配。**

### 定律 7：稀疏是效率的通用解（§11、§14）

MoE 稀疏激活、GQA/MLA 稀疏缓存、SAE 稀疏特征、大脑稀疏放电。
**用结构化的稀疏性逼近稠密计算的效果**，是自然与工程共同的省钱方式。

### 定律 8：记忆必须分层（§7、§12、§15）

权重（长期、慢）、上下文（短期、快）、外部库（无限、可溯源）。
**任何有限资源的系统，都会演化出"快而小"与"慢而大"的两级存储**——
CPU 的寄存器/内存/磁盘、人的工作记忆/长时记忆，都是如此。

### 定律 9：评测是代理，代理会被优化（§13）

分数是能力的代理，一旦成为目标，就会被 Goodhart。基准会污染、judge 会偏见、Elo 会谄媚。
**唯一可靠的评测，是持续更新题目 + 多指标 + 真实任务。**

### 定律 10：可靠性 = 单步 × 步数（§15）

$0.95^{20} \approx 36\%$。长链条系统的可靠性由最弱环节与链条长度共同决定。
**不要追求"永不犯错"，要设计"错了能发现、能回滚"。**

## 16.3 如果你只记住三件事

1. **它是一个概率模型，不是一个知识库。**
   它的一切能力与缺陷，都源于"根据上文预测下一个 token"。
   它"知道"的，是训练数据里反复出现的模式；它"不知道"的，是没见过的世界。
2. **它的能力来自规模，它的可用性来自对齐。**
   大模型不一定好用，小模型也可以很好用（§8.4）。
   产品化的关键，往往不是"换更大的模型"，而是"把任务拆对、把上下文给对"。
3. **它没有"理解"的保证，只有"表现"的证据。**
   思维链可能不忠实（§9.9），注意力图可能不解释（§4.5），
   分数可能被污染（§13.4）。**要验证，不要相信。**

## 16.4 下一步：读什么、做什么

### 想读论文

从 `papers/README.md` 的"入门五篇"开始：

1. *Attention Is All You Need*（2017）——架构
2. *Language Models are Few-Shot Learners*（2020）——规模
3. *Training language models to follow instructions*（2022）——对齐
4. *Chain-of-Thought Prompting*（2022）——推理
5. *DeepSeek-R1*（2025）——RL 推理

读论文的方法：**先读摘要、图 1、结论；再读方法；最后才读实验细节。**
不要从头到尾读——那是审稿人的读法，不是学习者的读法。

### 想动手

- 用一个小模型（1B 以下）跑通"分词 → 前向 → 采样"，亲手看 logits 怎么变成文字；
- 实现一个最小的注意力（20 行 PyTorch），确认你理解 $QK^\top/\sqrt{d_k}$；
- 用 LoRA 微调一个模型做分类，感受"预训练 + 微调"；
- 搭一个最小 RAG：切块 → 嵌入 → 检索 → 拼 prompt；
- 用 ReAct 写一个能查天气/算数的 agent，观察它怎么失败。

### 想跟进前沿

- 论文：arXiv 的 `cs.CL`、`cs.LG`；NeurIPS/ICLR/ACL/COLM 的 oral；
- 博客：Transformer Circuits（可解释性）、Lilian Weng 的博客（综述）、

## 16.5 开放问题

这些问题没有答案，但决定了这个领域未来五年的走向：

1. **规模还会继续有效吗？** 数据墙之后，合成数据、自我博弈、世界模型能否接棒？
2. **推理的本质是什么？** CoT 是"真的在想"，还是"更长的模式匹配"？
   可解释性能不能给出判决？
3. **如何保证对齐？** 当模型能"假装对齐"（§8.7），我们怎么知道它真的对齐？
4. **智能体可靠吗？** 复合误差能不能被工程手段压到可接受？评测怎么做？
5. **理解与预测的边界在哪？** 一个只优化"下一个词"的系统，能走多远？
6. **能源与算力的极限？**  Scaling 的物理约束会不会先于理论约束到来？

> **跨领域对照**　这些问题和 17 世纪自然哲学的问题结构相似：
> "热是什么？""生命是什么？""智能是什么？"
> 每一次，我们都先有一个**工程近似**（蒸汽机、显微镜、神经网络），
> 再用它反过来定义问题。**工具先于理论，理论再重塑工具。**
> LLM 可能不是"智能"的答案，但它是目前最好的**探针**。

## 16.6 结语

你在第 1 章学到的那个四词表例子——`猫 0.6 / 狗 0.3 / 鱼 0.08 / 车 0.02`——
和今天几千亿参数的模型，在数学上是同一件事：**给一个分布，然后采样。**

差别只在规模、数据、对齐、以及我们围绕它建的工程。
这个领域最迷人的地方，也正在这里：

> **一个简单到可以写在一行里的目标，在最极端的规模下，
> 长出了没人能完全解释的能力。**

理解它，不需要膜拜，也不需要恐惧。只需要**一层一层地拆开，再一层一层地装回去**。
这门课给了你拆装的工具。剩下的，是你自己的问题了。
